# Creature port (creature_common.cpp, creatures.cpp) - task E report, port round 3, 2026-10-06

Files: `src/mcengine/creatures.h`, `creature_common.cpp` (shared code + wake timers), `creatures.cpp`
(per-type Table A handlers), `src/tests/creatures_test.cpp` + `creatures_test.cmake`. No
`tables/creatures.tables` was created: nothing in the translated ranges needs an extracted table (the
jump tables are `switch`es; the four u16 at 0x1ea40 belong to type 15, which is not ported).
`creatures_test.exe` -> exit 0, zero warnings (/W4), built in `build_E` only.

Headline results:

- **The snapshot is a 412-tick reference, not just a moment.** Level 38 generated by the port and run
  for 412 ticks with empty command packets (the recording player hovered, port_player.md) reproduces
  **128 of the snapshot's creature slots byte for byte** (every field except the three list links):
  position, heading, per-thing RNG, countdowns, wake timers, state, sprite. The slots that differ all
  trace back to subsystems that are not linked into this test (see "Verification").
- No creature code calls the target selection / line-of-fire functions of task A (byte scan for
  `e8 rel32` from 0x18050..0x1f6b0 into 0x43f30..0x468e0: no hit). **No hook is needed**; the attack
  callbacks create their projectiles with `thing_create` and aim with `pos_angle_to` / `pos_pitch_to`.
- The state layout in ENGINE.md is off by one: **base = type * 6**, `+0` type-specific, `+1` main,
  `+2` attack, `+3` follow, `+4` dying, `+5` dead (details under "Corrections").

## Deviations and gaps

- `tick % desc.think_period` and the volley's `mana * 7 / mana_total` fault on a zero divisor in the
  original; the port treats a zero period as "never" and zero total mana as "one shot".
- `creature_dead_drop_mana` calls `g_hook_thing_drop_mana_ball` (spatial.h, installed by the effects
  owner); while it is null no mana ball is dropped.
- The test, not the engine, emulates the recording build's castle capacity (see request 3).
- Shared helpers (`think_now`, `sight_sq`, `nearest_in_list`, ...) are private to the two .cpp files;
  the per-type files of next round can use `creature_apply_damage` / `creature_wander_turn` from the
  header for the two inlined blocks every handler repeats.

## Requested shared-file changes

1. `mc_types.h` `MoveDesc`: `clear_lo` (+0xa) / `clear_hi` (+0xc) are named the wrong way round for
   creatures: 181e0 calls `pos_follow_ground(pos, ground, desc+0xc, desc+0xa, desc+0xe)`, i.e. +0xc is
   the lower and +0xa the upper clearance (villager descriptor: +0xa = 256, +0xc = 0). `turn_min` (+2)
   is the maximum yaw step per tick, `unk4` (+4) the unused third argument of `angle_turn_step`,
   `unk10` (+0x10) also the steepest slope a creature walks (`terrain_slope_at` limit).
2. `mc_types.h` comments: `Thing.turn_rate` (+0x82) is a *speed* for creatures (follower speed bonus,
   stroll speed of villagers, the bee's retreat speed); `Thing.cast_ticks` (+0x30) = |dy| to the local
   player at the last wake reload; `Thing.castle_size` (+0x47) = skeleton pose flag;
   `PlayerBlock.timer210` = "wanted by the villagers" (200 when the wizard hurts a builder / townie /
   trader / wizard castle or is shot at by an archer; archers attack only wanted wizards).
3. `level_features.cpp` `effect_wizard_init`: the retail `>> 4` is right for the retail exe; a switch
   for the recording build's `>> 2` (it changes how many townies a castle takes, hence everything
   downstream) would let replay tests run without the per-tick fix-up my test does.
4. `gen/dispatch_tables.h` / `tools/port/gen_dispatch.py` names: the `+0` state of each type carries
   the previous type's name (`creature_generic_s0` is the dragon's idle state, `creature_dragon_s6` the
   vulture's, `creature_griffon_s54` the skeleton's rising state, `creature_skeleton_s60` the emu's,
   `creature_genie_s72_place_castle` the **builder's**, `creature_builder_s78` the townie's,
   `creature_townie_s84` the trader's, `creature_trader_s90` type 15's). Binding is by address, so
   nothing breaks; only the names mislead.
5. Integration: a replay test with every subsystem registered (see Verification 1).

## Corrections to ENGINE.md / agent notes

- **State layout** (Region A 2.3): six states per type starting at `type * 6`: +0 type-specific, +1
  main (`creature_ai_step` or own code; the state most constructors set), +2 attack, +3 follow, +4
  dying, +5 dead. The shared bodies take `base = type * 6` and set base + 1..4; `creature_die` sets
  base + 5. `creature_attack_target` has three stack arguments (thing, base, callback), not four.
  `creature_follow_leader` switches on `leader.state - base`: 0, 1 follow; 2 take the leader's target;
  3 adopt the leader's leader; else drop it.
- **Awake gate** (Round 4 open question "what sets +0x3a"): `creature_proximity_wake_timer_46960`
  (0x10 when the creature is within 0x1800 xy of the **local** player's thing, segments get 0x12),
  the constructors (stagger) and `creature_wake_tick_468e0` (0xfa for dead creatures). It also writes
  `+0x30 = isqrt(dy^2)`: the caller pushes the EDX left by `pos_dist_sq_xy_3e970` (the dy term)
  instead of the result. Asleep creatures still move and think but neither consume damage nor look for
  enemies; the wake tick is skipped while `Config.flags & 0x10`.
- Damage intake clears only the attacker word of slot 0; the amount stays (visible in the snapshot:
  trader 392 has health 700 and amount 300 left).
- **Skeleton**: state 54 is the rising animation the constructor starts in; state 55 walks toward the
  nearest castle of another owner *anywhere on the map* (random turns only when there is none) and
  attacks inside sight radius + castle half width; while awake any player-list thing of another owner
  in sight / fov is attacked; conversions use the lists Archer / Builder / Townie in turn per think
  tick; the pose starts after 400 asleep ticks (50 after an attack), `aux = -50` when it is broken off.
- **Builder**: state 72 (1d540, named after the genie) is the builder's: up to four attempts east /
  west / south / north of the target wizard castle; after founding one the builder continues in state
  0x4f, i.e. as a townie, with type 0xc. States 73 / 75 / 74: wander for `aux` think ticks, pick the
  nearest wizard castle (3D distance > 0), walk to within 0xa00.
- **Townie / trader**: pick the nearest wizard castle (trader: the nearest farther than 0x3c00), walk
  to within 0x800 and enter when `castle.speed_base > castle.aux` (state base + 4 with aux = 1 deletes
  the villager, castle.aux++); a full castle is forgotten and the villager strolls at +0x82 speed.
- **Archer**: attacks only wizards with P+0x210 != 0 (checked every 4th think tick) and skeletons;
  re-arms P+0x210 = 200 while shooting; with a wizard-castle target it walks into it (within 0x1000,
  no capacity test). The villagers' "blame" (P+0x210 = 200) tests the attacker's type (0 or 1) but not
  its class.
- `creature_die`: kill credit only when the killer is a class-3 type-0 thing, the creature is its own
  owner, is not type 9 / 0xc / 0xd / 0xe / 0xf, and (for type 9) has no mana owner.
- `creature_attack_volley`: n = mana * 7 / mana_total; kind = (rng % (n * 100)) / 100 with the
  unclamped n, then n is clamped to 1..5; kind 0 -> n shots of type 0 (descriptors 6 - i, damage 400),
  1 / 2 -> n - 1 shots of type 9 (impact 0x17, damage 800), 3..6 -> one type 3 (impact 0x11, descriptor
  0x96a70, damage 8000); the result is whether the last `thing_create` succeeded.
- `creature_attack_fire_homing_desc_19a90` ends with `thing_move_to(projectile, creature position)`,
  which undoes its z raise.
