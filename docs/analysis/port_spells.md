Structure: the 15 projectile handlers share three frames that I diffed instruction by instruction
against the first of each kind and kept as three small drivers (`spell_cast_burst`: 47130 / 475b0 /
48c20 / 48de0 / 49140 / 492e0; `spell_cast_single`: 479f0 / 47b90 / 47d40 / 480e0 / 482f0 / 48510 /
488a0 / 48a70, and 47840 with `charge_every_tick = false`), each with a per-spell `launch_*`
function that holds exactly the field writes of that handler. What the diff found (i.e. where the
handlers are *not* copies of each other):

- 47840 (earthquake) jumps past `spell_charge_mana` on the non-launch ticks; all other one-shot
  handlers call it on every cast tick.
- 480e0 (rubber band) does not add the caster's speed and does not touch the aim charge.
- 475b0 (possession) writes aux = 0xc8, clears the aim charge without reading it, copies no damage.
- 482f0 (steal mana) copies the spell's damage and then overwrites it with 0x7d0.
- 488a0 (skeleton) sets damage 1, or the spell's mana_total when the caster's castle has
  mana_total >= that.
- 48a70 (thunderbolt) is the only one whose impact pair is class 9 (9 / 9).
- 49140 makes no sound request.
- target point: pitch = caster pitch and 0x4000 (0, 13, 15, 17, 18, 19, 20, 22, 23) or 0x2800
  (3, 7, 11); pitch 0, 0x1000 ahead, z snapped to the ground (6, 8, 9, and the castle seed).

## 3. Deviations and gaps

- Indices the original multiplies by 0xa4 unchecked (caster, castle, book slots, projectile child)
  read as "none" when outside the pool; `spell_dropped_update` returns 0 for a spell type outside
  0..23 instead of indexing P+0x2a4 out of range. Neither can trigger on valid state.
- DAT_000943c4 is kept as a file-local variable. Only 46dd0 references it (two direct references in
  the whole image, at 0x46dd9 and 0x46e1f: the clear and the test), so the branch that would copy the sealed flag to the copy
  left behind never runs; the copy of a sealed level pickup is therefore unsealed. Translated as is.
- FUN_0003fbf0 (called by the two speed handlers with the caster) is a lone `ret`; left as a comment.
- Not verified against original data: every cast path (see section 2). An emulator run of the
  original handler code on the snapshot state would give bit-exact ground truth for them; that
  needs an x86 emulator package (e.g. unicorn), which is not installed here.
- The Castle spell stays busy forever in my test builds because the seed projectile (45530, task A)
  and the castle handlers (task D) are not linked there.

## 8. Corrections and additions to ENGINE.md / agent notes

- agent4_C / ENGINE.md "every tick spell_charge_mana" is wrong for **spell_earthquake_update_47840**:
  it charges on the launch tick only, so (unlike every other cast) mana keeps regenerating during
  the 51 earthquake ticks.
- 46dd0: the flag is 0x40000 (not 0x400), and "phase 2 = owned copy" is the wrong way round: the
  picked Thing itself becomes the owner's phase-0 spell; the *new* Thing stays in phase 2.
- Table A state 68 (phase 2 of spell 22) is bound to the cast handler 0x49140, not to 0x47300: a
  level pickup of spell 22 can never be picked up (its handler returns at cast_ticks <= 0).
- Level records (thing.cpp, already translated): SwiId 3..5 = phases 0..2 of a *sealed* spell.
- Castle spell: cast_ticks == duration - 1 is the busy state; a failed `spell_can_cast` (caster dead
  or mana < 0) resets it to 0.
- Heal charges mana_total (1000) per tick for 5 % health; it stops as soon as mana < 1000.
- Invisible (48250) zeroes P+0x14b through the *spell's* player pointer (ebx = spell), which is
  the dummy block for every spell Thing (confirmed: all 39 snapshot spells have Thing.player = dummy):
  a no-op, presumably meant for the caster. Caster flag 0x20 is the same bit the dead flyer carries;
  player_cast_spell_410f0 clears it, so casting anything ends invisibility.
- Flags: caster 0x4000 shield (set every cast tick, never cleared here), 0x8000 rebound (cleared by
  the first idle tick of the spell), spell Thing 0x80 = speed sound requested.
- Teleport is the only handler in the range that draws from an RNG (the spell Thing's own).
- Interplay worth knowing (player.cpp is correct, this is how the original behaves):
  player_cast_spell runs before the flyer applies the pending charge, so with the key held it re-arms
  the spell on mana that is about to be taken; the handler then refuses (sound 0x1d) and the cast
  ends at once. Hence the steady fireball rate of one shot per 3 ticks at 100 mana per tick, with
  one "cannot" sound per shot.
- Names: projectile 1 = possession / homing shot, 0x11 = its large variant (spell 19), 0x10 = spell
  20, 0x12 = spell 22, 0xa = castle seed, 0xb = skeleton army seed, 0xc = thunderbolt carrier.
